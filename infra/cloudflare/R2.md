# DraftOS on Cloudflare R2

R2 is object storage with an S3-compatible API and **no egress fees** — ideal for
serving ISO images and package repositories at scale for free. This document is
the layout and the one-time setup runbook.

> Placeholders to replace: `<ACCOUNT_ID>`, `<BUCKET>` (suggested: `draftos-cdn`),
> and a public base URL (`https://pub-xxxx.r2.dev` for free, or a custom domain
> like `https://cdn.draftos.org`).

## Bucket layout

```
<BUCKET>/
├── iso/                      # installable ISO images + checksums
│   ├── draftos-desktop-<ver>-x86_64.iso
│   └── draftos-desktop-<ver>-x86_64.iso.sha256
├── repo/                     # pacman repository (Desktop edition)
│   └── x86_64/
│       ├── *.pkg.tar.zst
│       └── draftos.db.tar.gz          (repo-add output; keep the .db symlink)
├── flatpak/                  # ostree repo for the DraftOS Store's first-party apps
│   ├── draftos.flatpakrepo            # the remote descriptor users install
│   └── repo/                          # ostree objects + summary
└── images/                   # arkdep image tarballs (Immutable edition)
    └── draftos-cosmic-<ver>.tar.zst
```

## One-time setup (in the Cloudflare dashboard)

1. **Create the bucket.** R2 → *Create bucket* → name it `<BUCKET>`.
2. **Make it publicly readable** for downloads:
   - Either enable the free **r2.dev subdomain** (bucket → Settings → Public
     access → *Allow*), which gives `https://pub-xxxx.r2.dev/...`, **or**
   - Connect a **custom domain** (bucket → Settings → *Connect Domain* →
     `cdn.draftos.org`) — recommended for stable URLs and full CDN caching.
3. **Create an S3 API token** for uploads: R2 → *Manage API Tokens* →
   *Create token* → **Object Read & Write**, scoped to `<BUCKET>`. Save the
   **Access Key ID** and **Secret Access Key** (shown once). Your account id is in
   the R2 endpoint `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.

That's it for read-serving — public R2 buckets support HTTP range requests, so ISO
downloads can resume. The optional Worker (below) is only for nicer indexes.

## Uploading

Configure rclone once from [`rclone.conf.example`](rclone.conf.example), then:

```bash
# whole tree
infra/cloudflare/upload.sh dist/

# just the ISOs
infra/cloudflare/upload.sh dist/iso iso
```

CI does this automatically for release assets — see
[`.github/workflows/publish-r2.yml`](../../.github/workflows/publish-r2.yml). Add
these repository **secrets**: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`,
`R2_SECRET_ACCESS_KEY`, `R2_BUCKET`.

## How users consume it

**pacman repo** (Desktop edition) — in `/etc/pacman.conf`:

```ini
[draftos]
Server = https://cdn.draftos.org/repo/$arch
```

Build the `.db` with `repo-add draftos.db.tar.gz *.pkg.tar.zst` before uploading
`repo/x86_64/`.

**Flatpak repo** — export apps with `flatpak build-export`, then publish `flatpak/`
and have users run:

```bash
flatpak remote-add --if-not-exists draftos https://cdn.draftos.org/flatpak/draftos.flatpakrepo
```

**ISO download** — link straight to `https://cdn.draftos.org/iso/…` from the site
and GitHub Releases.

## Optional: the serving Worker

A public bucket already works. Deploy the Worker in `worker/` only if you want
auto-generated directory index pages and custom cache rules. It requires
[`wrangler`](https://developers.cloudflare.com/workers/wrangler/):

```bash
cd infra/cloudflare
wrangler deploy            # binds the BUCKET and (optionally) your custom domain
```
